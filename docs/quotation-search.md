# 報價分頁與搜尋

報價紀錄預設每頁 20 筆，可選 50 或 100 筆，使用上一頁／下一頁瀏覽。搜尋報價編號、快照中的客戶名稱／代碼、城市／機場及國家名稱／代碼；客戶、狀態、海空運條件會一起篩選。更改搜尋、篩選或每頁筆數會回到第一頁，顯示符合條件的總筆數。搜尋內容不放進網址。

清單只下載當頁摘要，明細及修訂來源按需讀取單筆完整快照。總覽的報價總數／Quoted／Accepted 使用全體有效紀錄的統計，最近報價最多六筆；總數不由目前頁面推算。已刪報價排除於清單與統計，刪除最後一頁的末筆時會回到剩餘的最後一頁。

## API

`GET /api/quotes` 改為分頁回應：

```json
{"items":[],"page":1,"pageSize":20,"total":0,"totalPages":1}
```

| 參數 | 規則 |
| --- | --- |
| `page` | 從 1 起的正整數，最多 1,000,000；超過實際頁數會夾回最後一頁 |
| `pageSize` | 20、50 或 100，預設 20 |
| `q` | 最多 120 字的搜尋文字；`%`、`_` 以字面搜尋 |
| `customerId` | 客戶識別碼，可留空 |
| `status` | Draft、Quoted、Accepted、Rejected、Expired，可留空 |
| `transportMode` | AIR、SEA，可留空 |

列表依建立時間及 ID 倒序排列，條件相交；總數與當頁資料在同一資料庫交易中讀取。查詢採參數綁定，無效參數回應 400。

`GET /api/quotes/overview` 回應 `total`、`quoted`、`accepted` 及最多六筆 `recent` 摘要。`GET /api/quotes/:id` 維持完整快照，PDF 與單筆刪除端點沿用原介面。清單項目不含 `snapshot`，既有 API 使用者須從原本的陣列讀取方式改為讀取 `items`。

## 資料與升級

新增 migration `20261106000600_quote_list_summaries`，將歷史快照中的列表資訊填入獨立摘要欄位並建立索引，沒有重寫原始 snapshot。新報價會在保存快照的同一交易中保存摘要；客戶之後改名不會改寫既有報價顯示的名稱。

首次升級需要回填既有報價，資料較多時請等待 migration 完成，再開啟預覽。

首次查詢會再以每批 200 筆的輕量摘要完成 Unicode 正規化，讓舊的全形文字、英文大小寫及「台／臺」與新資料使用相同搜尋規則。這個步驟不讀取完整快照、不修改原始報價，只更新搜尋欄位；已完成的紀錄不會重複處理。

查詢只選摘要欄位，不讀取全部報價的 JSON／Logo。文字包含搜尋仍可能掃描符合條件的摘要列，這項功能不代表任意資料量都有固定回應時間；客戶、狀態、運輸方式及日期排序可使用資料庫索引。

更新前依既有備份流程保存 SQLite，再停止預覽、拉取最新程式、安裝鎖定依賴並執行 `npm run codespaces:start`，由啟動流程套用 migration。不要刪除資料庫或使用 `migrate reset`。
