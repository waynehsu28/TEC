# 新增報價返回營運總覽：檢查與修正

## 可確認的原因與範圍

舊程式使用 `useState('dashboard')` 保存目前功能，網址沒有功能位置。瀏覽器驗證中，點擊「新增報價」可以進入表單，但其後重新載入文件會直接回到營運總覽。程式中沒有刻意把新增報價轉回總覽的 redirect，正常導覽按鈕也不位於表單內。

舊 Codespaces 啟動器使用 `next dev`。Next.js 開發模式可能在編譯更新、HMR 重連失敗或編譯版本變更時重新載入文件，這會觸發上述狀態遺失。但這次沒有直接連入使用者的 GitHub Codespace，不能斷定「首次點擊立即跳回」由哪一次平台重連或瀏覽器事件觸發。

## 已修正

- 以 URL hash 保存功能、歷史選取、客戶篩選與修訂來源，支援重新整理及上一頁／下一頁。URL 不包含貨物、客戶名稱、售價或成本。
- 初始載入先恢復功能位置，避免短暫顯示錯誤的營運總覽畫面。
- 報價草稿在同分頁暫存，依新報價／不同修訂分開；正式儲存仍使用資料庫。恢復後重新驗證合約與試算。
- 延遲儲存只更新資料與提示，不搶走使用者後來切換的功能或新開的草稿；成功保存後也只清除相同內容的暫存。
- 儲存期間鎖定報價欄位；過期試算的成功與失敗回應都不套用到新輸入。
- 畫面渲染失敗時保留當前功能並顯示重試，不自動返回總覽。
- Dashboard 合約數依當日適用版本計算，未來生效版本不會隱藏仍有效的舊版本。
- Codespaces 日常預覽改為 production：停止服務後啟動會先遷移、重新建置，再以 `npm start` 執行。沒有 HMR；手動除錯仍可用 `npm run dev`。

## 驗證證據

完整命令與數量見 [驗收紀錄](acceptance.md)。新增實際 React／DOM 測試，涵蓋 URL 恢復、草稿、Back、晚到的儲存、離開又返回同一頁、儲存鎖定、過期錯誤與渲染失敗。

另外以 Chromium，將真實 HTTP 流量經本機模擬的 Codespaces HTTPS 代理轉送到已編譯的 production 服務，驗證點擊沒有文件重載；重新整理、歷史選取、修訂草稿與 Back／Forward 正常恢復；延遲儲存不刪除新草稿、不搶走頁面。瀏覽器沒有 page error，也沒有 HMR WebSocket 連線。

## 已有 Codespace 的更新

先儲存現有內容並停止服務：

```bash
npm run codespaces:stop
```

停止其他手動啟動的資料庫工具後，先下載備份 `prisma/dev.db`，再執行：

```bash
git pull --ff-only origin main
npm ci --ignore-scripts
npm run codespaces:start
```

這次加入了介面測試依賴，因此需要重新安裝鎖定依賴。啟動器會遷移並重新編譯目前程式，看到 ready 後重新開啟 Private 的 3000 預覽。不要刪除 SQLite，也不要用 `migrate reset`。
