# MVP 商業規則與假設

以下規則讓未指定的情境可以被驗證。它們是本系統的計算行為，不代表任何客戶已接受的合約條款；使用者必須依實際合約建檔。

## 運輸方式、國家價與計價單位

- 新增表單預設為 AIR／COUNTRY。國家使用 ISO 3166-1 alpha-2 代碼，例如台灣 `TW`、美國 `US`，畫面提供國家名稱選單。
- COUNTRY 合約以客戶、運輸方式及起運／目的國家匹配，適用目的國內任意城市、港口或地區。可選填的起運地／目的地文字只供描述，不縮小國家價的適用範圍。
- AIR 基本運費採 `PER_KG`；SEA 散貨 LCL 採 `PER_CBM`；SEA 整櫃 FCL 採 `PER_CONTAINER`，櫃型為 `20GP`、`40GP` 或 `40HQ`。一張 FCL 報價只能有一種櫃型，櫃數為正整數。
- 每份合約明確標記已包含哪些費用。「全國適用」或 `ALL_IN` 不會自動包含派送、偏遠地區、燃油、報關或其他費用；應依真實合約逐項建檔。
- 原有 AIR／AIRPORT 合約仍以 3 碼 IATA 機場路線比對。沒有運輸／範圍欄位的舊 API 輸入維持 AIR／AIRPORT 預設，避免把舊機場價當國家價；SEA 只能使用 COUNTRY。

## 貨物、空運計費重量與海運數量

- 每組資料是一種尺寸與重量條件；`pieces` 為該組件數，尺寸單位為 cm。
- `PER_PIECE`：`grossWeight` 是單件重量，整組實重為單件重量 × 件數。
- `GROUP_TOTAL`：`grossWeight` 是整組總實重，不再乘件數。
- 每組 CBM = 長 × 寬 × 高 × 件數 ÷ 1,000,000。
- 空運每組材積重 = 長 × 寬 × 高 × 件數 ÷ 材積除數。預設除數為 6000，可在 Settings 修改。
- 空運先加總所有組別的實重與材積重，再取兩者較大值，最後向上進位至設定的重量單位；預設為 0.5 KG。不得先將每組進位。
- 空運材積重量在報價畫面、歷史與 PDF 固定顯示兩位小數，採 HALF_UP 四捨五入；只格式化顯示，不截斷計算或快照原始精度。計費重量及級距選價仍使用原始精確值，海運 CBM 不套用此兩位小數格式。
- 空運範例：10 件、每件 70 × 60 × 60 cm、單件實重 35 KG，總實重 350 KG、材積重 420 KG、計費重 420 KG。
- 海運 LCL 的計價數量是所有貨物的 CBM 加總；保留十進位精度，不套用 6000 材積除數或空運 0.5 KG 進位。海運不產生空運材積重／計費重。
- 海運 FCL 的計價數量是櫃數。可不填貨物明細，此時重量、CBM 與件數為未提供，不能解讀為已知零值；若有按 KG、CBM 或件數收取的未含費用，必須補上貨物明細，否則拒絕計算。
- 海運本版不做 W/M、RT、重量／體積擇大或按 KG 的基本運費計算。

## 合約匹配與版本

- 只搜尋指定客戶啟用中的合約。在每條合約路線的版本鏈中，先選擇「有效期間涵蓋出貨日的最高版本」，再比對客戶、運輸方式、路線範圍、起運／目的國家（COUNTRY）或機場（AIRPORT）及其他條件。尚未生效的未來版本不會提前停用仍適用的舊版本。
- 合約有效起訖日均包含當日。日期是 `YYYY-MM-DD` 日曆日期，不以輸入時間加減一天。
- 承運人（航空／船公司）、服務類型、貨物種類若有指定，必須與報價相符；空白代表該條件不限。國家代碼、機場、承運人、服務類型、貨物種類以去除首尾空白並轉大寫後比對，客戶 ID 則須完全相同。海運另外比對 LCL／FCL，FCL 須比對櫃型。
- 承運人專屬合約優先於不限定承運人的合約。仍有多份候選時，不以最低價或第一筆自動決定，由使用者選擇合約與版本。
- 無適用合約時顯示 `No Valid Contract Rate`，允許輸入手動非合約售價。不得把成本自動當售價。
- 唯一性為「客戶＋合約編號＋路線條件」。同一客戶可用相同合約編號維護不同路線。國家路線條件包括運輸方式、路線範圍、起運／目的國家、承運人、服務類型、貨物種類，以及海運類型／櫃型；描述城市或港口不形成另一個國家價格。既有機場路線保留原機場條件。每條路線有獨立版本鏈，完全相同的組合不得重複建檔。
- 更新合約建立新版本，不修改既有版本。歷史報價固定引用當時版本與價格；停用及到期不會刪除舊快照。
- 修訂報價建立新紀錄，不覆寫來源。修訂時重新核對目前輸入條件與可用合約；若重選合約，請重新確認附加費調整。

## MIN、Normal 與數量級距

- 一票只採用一個基本運費單價，不做累進計價。空運數量為計費重 KG，海運 LCL 為 CBM，海運 FCL 為櫃數；級距門檻使用該合約相同的計價單位。
- 對本次計價數量，選擇「門檻小於或等於計價數量」的最高已填級距。
- 尚未達到任何已填級距時使用 Normal Rate。
- 空運表格以 Normal 列維護 45 KG 以下的小重量單價。最小已填門檻為 +45 時，未滿 45 KG 使用 Normal，45 KG 起（含）選擇已達門檻的最高級距；重量先完成進位，再選價。Normal 列依最小已填門檻顯示實際範圍，自訂 +30、只有 +100 或沒有級距時不會誤標為固定 45 KG 以下。既有 Normal 單價直接帶入，儲存不新增零或負門檻。
- 基本運費為所選單價 × 計價數量，再與 Minimum Charge 比較，取較大值。MIN 是整票最低收費，不是每 KG、CBM 或每櫃的單價。
- 沒有可用級距或 Normal Rate、但有 MIN 時，依已建檔 MIN 收取固定基本運費；三者皆無法提供可用價格時，拒絕計算並要求補齊設定。
- 級距價格可留白；留白不等於零。系統不採用尚未達到的較高門檻尋找更低整票價，不提供 Weight Break Optimization。
- 空運示意：420 KG × USD 4.30/KG = USD 1,806.00，適用級距為 +300 KG（假設沒有更高且已達門檻的其他級距）。此價格為 Demo，並非實際運價。

## 附加費與臨時調整

| 計價方式 | 規則 |
| --- | --- |
| Per KG | 空運：單價 × 計費重；海運：單價 × 貨物總實重 |
| 重量級距 Per KG（PER_KG_TIERED） | 依該項費用的重量級距選單價，再乘整票重量；空運用進位後計費重，海運用總實重 |
| Per CBM | 單價 × 貨物總 CBM |
| Per Container | 單價 × FCL 櫃數；空運與 LCL 不適用 |
| Per Shipment | 每票固定金額 |
| Per Piece | 單價 × 全部件數 |
| Minimum Charge | 該費用的每票固定最低金額，不是單位價格 |
| Manual Amount | 本次手動指定金額 |

每種附加費皆可另設該費用最低金額（若已建檔），計算後取較大值。已標記「包含於基本運價」的費用會顯示已含，不再加入應收合計，也不要求為已含項目補填計費數量。All-in 名稱本身不推測包含哪些項目，仍由使用者明確標記；國家價也不自動代表含目的國派送或偏遠地區費。

Trucking Charge 等附加費可選「重量級距 Per KG」。每項費用的 Normal 與 +45／+100／+300／+500／+1000 KG、自訂級距皆獨立於基本運費及其他費用。依適用重量選最高已達門檻，未達首個已填門檻時用該項 Normal；所選單價乘整票重量，不分段累進，也不試用較高門檻做 Weight Break Optimization。`minimumAmount` 是該項固定最低金額；沒有可用級距或 Normal 但有最低金額時按該最低金額收取，三者皆缺時拒絕計算。海運 FCL 未提供貨物重量時，未含的重量級距費用仍須先補貨物資料。

報價可調整個別費用單價或手動金額，也可增加臨時費用。快照同時保存合約原始單價／金額與本次套用單價／金額，不回寫合約。已含費用不因調整單價而重複收取。若臨時應收費用的名稱與已含合約費用相同（去首尾空白並轉大寫比對），系統拒絕新增，避免以臨時費用重複計收。

重量級距費用的本次調整針對已選出的單價，不修改合約級距表。臨時費用也可使用相同級距計價，表格內容隨目前分頁的報價草稿保存。新快照與 PDF 保留該費用實際使用的 KG、級距與單價；舊快照不補算或改寫。migration `20261105000300_tiered_charge_rates` 新增合約附加費級距關聯表與報價套用紀錄欄位，更新時保留原資料庫並套用 migration。

## 幣別、精度與匯率

- 金額、運價及匯率使用十進位字串保存，使用 Decimal.js 計算；不以 JavaScript 浮點數做財務運算。
- 幣別支援 USD、TWD；金額顯示兩位小數。金額採四捨五入（half-up），空運計費重向上進位，海運 CBM 不套用空運重量進位。
- 基本運費與每項附加費先四捨五入至兩位小數。每項成本亦先四捨五入至兩位小數，再依原幣別加總；需要換匯時，轉換各幣別小計後相加，再四捨五入至兩位小數。毛利由這些已確定的收入與成本總額相減，百分比顯示兩位小數。
- 匯率方向固定：`1 USD = fxRate TWD`。USD 轉 TWD 乘匯率，TWD 轉 USD 除匯率；匯率使用日另外保存。
- Settings 預設 `CUSTOMS`／`EXPORT`：海關三旬匯率，出口選 `buyValue`（買進），可切換進口 `sellValue`（賣出）。這是應用程式明示的欄位選擇，不代表已取得官方法規佐證其法定進出口分類。手動來源 `MANUAL` 持續可選，新報價依 Settings 的來源建立。
- 自動來源固定為 [官方 GC331 CURRENT_JSON](https://portal.sw.nat.gov.tw/APGQ/GC331!downLoad?formBean.downLoadFile=CURRENT_JSON)，僅涵蓋回應的當期 `start`／`end`，以出貨日核對適用期間；不提供歷史或未公告未來期間。超期、缺 USD、格式錯誤、逾時或連線失敗均拒絕自動取率，不以過期資料或第三方備援替代；使用者可明確切換手動輸入。
- 自動取率的預覽與儲存由伺服器依出貨日及類別取得權威值，覆寫瀏覽器傳入的匯率。`snapshot.input.customsRate` 保存匯率、使用日、類別、適用起訖日、官方來源 URL 與取得時間；之後不重新取率改寫舊報價。舊報價或草稿若缺來源，視為 `MANUAL`，不因新預設而改用海關匯率。操作與來源確認範圍見 [海關匯率說明](customs-exchange-rates.md)。
- 成本與售價可以不同幣別。只有具備必要匯率才可計算報價分析幣別的合併總額；缺匯率時保留各幣別明細與小計，不能把跨幣別數值直接相加。
- 不自行加入稅額、燃油費、保險、法律條款或其他未建檔費用，也不依 Incoterms 自動判定關稅、報關或派送責任。

## 成本、毛利與狀態

- 成本是獨立輸入資料，可標記 Estimated 或 Actual，不能反向更動客戶售價。
- 沒有提供成本時顯示 `Cost Not Available`；未知成本不等於實際零成本，不計算完整毛利與毛利率。
- 有部分成本未輸入，或尚未確認完整時，只顯示已知成本與暫估利潤，清楚標示不完整；不顯示完整毛利率或 Markup。明確輸入零代表已知零成本，與空白不同。
- 即使成本項目齊全，若有 Estimated，利潤仍屬暫估。使用者需自行確認所有必要成本已包含。
- Gross Profit = Revenue − Cost；Gross Profit Margin = Gross Profit ÷ Revenue × 100%；Markup = Gross Profit ÷ Cost × 100%。分母為零時不顯示無意義百分比。
- 成本大於售價顯示 `Negative Profit Warning`，不自動加價。
- 報價狀態：Draft、Quoted、Accepted、Rejected、Expired，由使用者在建立或修訂時保存；到期日不會自動修改已保存狀態。報價有效日可以早於預計出貨日，表示客戶須在該日前確認；不強制兩個日期的先後關係。狀態與效期是記錄資訊，不等同電子簽約、收款或法律效力。
- 每日流水號以 Asia/Taipei 日期編碼。原報價修訂序號為 1；後續修訂使用相同根單號加上 `-R002`、`-R003` 等尾碼。

## 保存與對外 PDF

- 客戶、合約、版本、重量級距、附加費、報價、貨物、費用、成本、修訂、設定、匯率均有資料庫紀錄。
- 報價使用交易保存；保存失敗不應留下部分貨物或費用紀錄。
- 新報價快照保留當時的運輸方式、路線範圍、國家、海運類型／櫃型、計價單位與數量，以及合約、價格、附加費、成本、匯率、貨物、客戶與公司資訊及自填條款。
- migration 只新增支援欄位，既有資料預設為 AIR／AIRPORT，不從 TPE、LAX 等代碼推測國家；已保存的舊快照 JSON 不改寫，仍以原有空運資訊顯示與產生 PDF。
- PDF 僅讀取該份已保存快照，採欄位白名單輸出對外內容。PDF 不輸出成本、毛利、毛利率、Markup。
- 使用者自己寫入條款或備註的內容不會自動辨認是否含內部機密，發出前仍須檢查。

## 本機資料庫實作

- SQLite 仍為本機 `prisma/dev.db` 檔案，使用 Prisma 官方 `@prisma/adapter-libsql`，不連線至付費雲端服務。
- Prisma Client 的 JavaScript client engine 已正式提供；Prisma 6.19 migration CLI 的 JavaScript adapter 設定仍是 experimental。版本固定於 lockfile，升級前應在備份副本重跑 schema migration、交易、快照與還原驗證。
- 公司 Logo 限 PNG/JPEG，解碼後最多 1 MiB，以資料 URI 保存至設定及報價快照，無需另外維護上傳檔案目錄。
